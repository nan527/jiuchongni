# 就宠你 — 智能匹配算法文档

> 最后更新：2026-06-16

---

## 一、算法概述

智能匹配采用 **两阶段架构**：

1. **AI 意图解析**：调用 AI 模型将用户自然语言转为结构化需求
2. **本地匹配评分**：硬性筛选（不通过直接排除）+ 软性评分（比例放大到 100 分）

---

## 二、AI 意图解析

### 2.1 调用方式

```
云函数: ai_handler
Action: smart_match_parse
超时: 60s
```

### 2.2 输入参数

```js
{
  action: 'smart_match_parse',
  userText: '在太原寄养一天，100元左右，要有监控',
  petInfo: {
    name: '小花',
    species: '猫',
    age: '成年',
    breed: '英短',
  }
}
```

### 2.3 输出格式

```js
{
  success: true,
  parsed: {
    serviceCategory: 'foster',   // 服务类别
    location: '太原',            // 用户指定的城市
    budget: { max: 100 },        // 预算范围
    keywords: ['监控'],           // 关键词
    preferences: [],              // 偏好标签
    urgency: 'normal',            // 紧急程度
  }
}
```

### 2.4 serviceCategory 枚举值

| 值 | 含义 | 触发示例 |
|---|------|---------|
| `foster` | 寄养 | "寄养一天"、"帮我照顾几天"、"出差需要人看宠物" |
| `grooming` | 美容 | "洗个澡"、"修个毛"、"美容"、"洗护" |
| `medical` | 医疗 | "打疫苗"、"做个检查"、"生病了" |
| `door` | 上门 | "上门喂养"、"来家里照顾"、"上门服务" |
| `null` | 不限 | 用户未指定服务类型 |

### 2.5 urgency 枚举值

| 值 | 含义 | 触发示例 |
|---|------|---------|
| `urgent` | 紧急 | "今天就要"、"马上"、"急" |
| `normal` | 正常 | 默认值 |

### 2.6 AI 解析失败降级

当 AI 返回格式异常时，自动降级到 `fallbackSmartMatch` 函数，通过正则表达式提取关键信息：
- 服务类型：通过关键词正则匹配（如 `/寄养|托管|看护/` → `foster`）
- 地区：提取城市名
- 预算：提取数字
- 关键词/偏好：基于规则提取

## 四、硬性筛选

硬性筛选不通过的服务直接排除，不进入评分阶段。

### 4.1 服务类型筛选

```js
if (parsed.serviceCategory) {
  filtered = filtered.filter(({ service }) =>
    service.category === parsed.serviceCategory
  );
}
```

### 4.2 地区匹配

匹配逻辑（`_isLocationMatch`）：

1. **直接匹配**：机构区域包含用户城市，或用户城市包含机构区域
2. **省份→城市匹配**：用户说省份（如"黑龙江"），机构城市在该省（如"哈尔滨"）
3. **城市→省份匹配**：用户说城市（如"太原"），机构省份名在该城市所属省（如"山西"）

覆盖 31 省主要城市。匹配前去掉"省"、"市"等后缀再比较。

### 4.3 预算筛选

```js
if (parsed.budget && parsed.budget.max) {
  filtered = filtered.filter(({ service }) => {
    const price = Number(service.price) || 0;
    return price <= parsed.budget.max;
  });
}
```

## 五、软性评分

通过硬性筛选的服务进入评分阶段。**满分 100 分**，采用比例放大机制。

### 5.1 评分公式

```js
_calcScore({ service, agency }, parsed, userLocation) {
  let earned = 25;    // 基础分
  let maxEarned = 25; // 基础分上限

  // 各维度按用户是否实际提到来决定是否计入总分
  // 最终: Math.round(earned / maxEarned * 100)
}
```

### 5.2 维度详情

| 维度 | 满分 | 计分规则 | 搜索范围 | 何时计入 |
|------|------|---------|---------|---------|
| 基础分 | 25 | 通过硬性筛选即得 | - | 始终 |
| 关键词匹配 | 40 | 每命中 1 个 +8，上限 40 | 服务名称/描述、机构介绍/服务范围/名称 | 始终 |
| 偏好匹配 | 30 | 每命中 1 个 +10，上限 30 | 服务名称/描述、机构介绍/服务范围/笼位描述 | 用户提到偏好时 |
| 价格适配度 | 15 | 越接近预算中心分越高 | - | 用户指定预算时 |
| 环境展示度 | 10 | 0张0分，1-2张5分，3+张10分 | 机构 envImages | 始终 |
| 紧急度加成 | 5 | 寄养服务且有空笼位时 +5 | - | 用户指定紧急时 |

### 5.3 比例放大机制

```js
// 只计算用户实际提到的维度，未提到的不计入总分
if (maxEarned <= 0) return 50;
return Math.min(Math.round(earned / maxEarned * 100), 100);
```

示例：
- 用户只说了"寄养猫咪"：基础25 + 关键词命中3个(24) = 49/65 → **75%**
- 用户说了"寄养猫咪，便宜点，要监控"：基础25 + 关键词(24) + 偏好(20) + 价格(15) + 环境(5) = 89/105 → **85%**

### 5.4 价格适配度详情

```js
if (parsed.budget && parsed.budget.max && price > 0) {
  maxEarned += 15;
  const budgetCenter = ((parsed.budget.min || 0) + parsed.budget.max) / 2 || parsed.budget.max;
  const diff = Math.abs(price - budgetCenter) / budgetCenter;
  if (diff <= 0.3) earned += 15;       // 接近预算中心
  else if (diff <= 0.6) earned += 10;  // 偏离较多
  else earned += 5;                     // 偏离很远
}
```

## 六、结果处理

### 6.1 排序与截断

```js
const results = scored
  .sort((a, b) => b.matchScore - a.matchScore)
  .slice(0, 10);
```

### 6.2 百分比与颜色

```js
r.matchPercent = Math.min(r.matchScore, 100);
```

四档颜色标识：

| 范围 | 颜色 | 类名 |
|------|------|------|
| 80%+ | 绿色 | `badge-high` |
| 50-80% | 橙色 | `badge-med` |
| 20-50% | 暖橙色 | `badge-low` |
| <20% | 灰色 | `badge-very-low` |

### 6.3 匹配理由生成

最多显示 3 条理由，优先显示硬性筛选理由，然后是关键词和偏好匹配理由。

## 七、完整流程图

```
用户输入自然语言 + 选择宠物
        ↓
  AI 解析需求（云函数 smart_match_parse）
  失败时降级到 fallbackSmartMatch
        ↓
  提取: serviceCategory, location, budget, keywords, preferences, urgency
        ↓
  查询所有已审核机构 + 服务（limit 100）
        ↓
  构建 (agency, service) 对
        ↓
  ┌─ 硬性筛选 ─────────────────────────┐
  │ 服务类型匹配 → 地区匹配 → 预算匹配 │
  └────────────────────────────────────┘
        ↓
  ┌─ 软性评分（满分 100，比例放大）─────┐
  │ 基础分 25                            │
  │ + 关键词匹配 (每命中+8, 上限40)     │
  │ + 偏好匹配 (每命中+10, 上限30)      │
  │ + 价格适配度 (+5/+10/+15)           │
  │ + 环境展示度 (0/5/10)               │
  │ + 紧急度加成 (+5)                    │
  │                                      │
  │ 最终: earned/maxEarned * 100         │
  └────────────────────────────────────┘
        ↓
  按分数降序排列，取前 10 条
        ↓
  批量解析服务封面图（cloud:// → HTTP URL）
        ↓
  生成匹配理由（同义词扩展匹配）
        ↓
  展示匹配结果列表（含四档颜色标识）
```

## 九、已知限制

1. **省市映射不完整**：仅覆盖 31 省主要城市，未覆盖地级市和县级市
2. **无 GPS 距离计算**：`agency_profiles` 无经纬度字段，无法计算真实距离
3. **服务数量限制**：每次查询最多 100 条服务（`limit(100)`）
4. **评分权重固定**：无法根据用户行为动态调整权重
